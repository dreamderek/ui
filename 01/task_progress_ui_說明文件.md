# 評鑑卡介面 V7：開發與操作說明

**對應頁面：** `評鑑卡介面設計_ui_v7.html`  
**形式：** 單一 HTML 原型；樣式與互動 JavaScript 皆內嵌於檔案中。  
**用途：** 以任務卡呈現進度、完成結果與申訴處理流程。

---

## 1. 介面總覽

畫面由上方主工作區與下方任務列組成。

| 區塊 | 位置與比例 | 顯示的任務 |
|---|---|---|
| 完成區 | 上方左側，約 60% | `completed` |
| 資訊區 | 上方右側，約 40% | 最後被指向的任務詳情與操作按鈕 |
| 申訴區 | 下方左側，約 40% | `appeal` |
| 任務卡區 | 下方右側，約 60% | `available` |

在螢幕寬度小於 760px 時，主工作區與下方列會改為單欄垂直排列，避免卡片與資訊內容被壓縮。

每張任務卡只會出現在一個區域：進行中任務只在任務卡區、已完成任務只在完成區、申訴中任務只在申訴區。

## 2. 任務狀態與流程

| 狀態 | 所在區域 | 可進行的狀態操作 |
|---|---|---|
| `available` | 任務卡區 | 標記完成 |
| `completed` | 完成區 | 提出申訴 |
| `appeal` | 申訴區 | 撤銷申訴 |

```text
任務卡區（available）
        │ 標記完成
        ▼
完成區（completed）
        │ 提出申訴
        ▼
申訴區（appeal）
        │ 撤銷申訴
        ▼
完成區（completed）
```

狀態變更只會更新 `task.status` 與必要的進度值，再由 `render()` 重新繪製畫面；不會以拖曳或調整陣列位置來決定排序。

## 3. 操作方式

### 查看資訊

將游標移到任一任務卡，資訊區會更新為該任務的：

- 任務名稱與詳細內容
- 完成度
- 目前狀態
- 操作按鈕

資訊區會保留「最後指向的任務」。游標離開卡片後內容不會清空，直到使用者指向另一張卡片。

### 從資訊區操作

資訊區提供以下按鈕：

- **查看詳情**：開啟任務操作對話框。
- **標記完成**：僅在進行中任務顯示，將任務移至完成區。
- **提出申訴**：僅在已完成任務顯示，將任務移至申訴區。
- **撤銷申訴**：僅在申訴中任務顯示，將任務移回完成區。

### 從卡片開啟操作對話框

雙擊任務卡可開啟對話框。對話框會依任務狀態顯示相符的操作：

- 進行中：標記完成
- 已完成：提出申訴
- 申訴中：撤銷申訴

單擊卡片不會開啟對話框。卡片不支援拖曳排序。

## 4. 排序、卡片排列與分頁

### 固定時間排序

所有區域都以 `createdAt` 由新到舊排序：左側是較新的任務，右側是較舊的任務。狀態變更不會改寫 `createdAt` 或 `tasks` 陣列順序。

### 水平牌組

完成區與申訴區皆採水平重疊牌組：

- 卡片從左至右排列。
- 間距會按容器寬度與卡片數量自動計算，最大展開距離為 78px，以降低卡片重疊。
- 指向卡片時，該卡片只會向上移動 12px，不會提高 `z-index` 至最上層，因此仍可選取被部分覆蓋的其他卡片。

### 自適應分頁

完成區與申訴區都有 ▲／▼ 翻頁控制。每頁卡片上限會依該區實際寬度計算，範圍為 3 至 10 張；寬度改變時會自動重新計算。

頁碼會顯示目前頁數、總頁數及每頁張數，例如：`1 / 3（每頁 6 張）`。翻頁流程為淡出目前卡片、更新資料後淡入新頁面。

新標記完成的任務會回到完成區第 1 頁；新提出申訴的任務會回到申訴區第 1 頁。

## 5. 任務資料結構

頁面目前使用 JavaScript 內建的示範資料。每筆任務包含：

```javascript
{
  id: 1,
  createdAt: "2026-09-15T09:00:00",
  title: "任務名稱",
  detail: "任務詳細內容",
  progress: 75,
  status: "available"
}
```

| 欄位 | 說明 |
|---|---|
| `id` | 任務唯一識別碼 |
| `createdAt` | 建立時間，也是區域內排序依據 |
| `title` | 卡片與資訊區標題 |
| `detail` | 資訊區與對話框的詳細描述 |
| `progress` | 進度百分比 |
| `status` | `available`、`completed` 或 `appeal` |

此版本的資料只存在瀏覽器記憶體；重新整理頁面後會回到 HTML 中宣告的初始示範資料。若要串接正式系統，應以 API 讀取任務清單，並在 `moveTask()` 中提交狀態異動。

## 6. 主要程式結構

| 函式／事件 | 職責 |
|---|---|
| `taskCard(task)` | 建立卡片 DOM，掛載懸停與雙擊事件。 |
| `showTaskInfo(task)` | 更新資訊區並記錄最後指向的任務。 |
| `openTaskDialog(task)` | 依狀態設定並開啟對話框。 |
| `render()` | 排序任務、繪製三個任務區、計算卡片間距、更新分頁與整體進度。 |
| `moveTask(id, status)` | 變更任務狀態，必要時回到對應區域的第一頁，然後呼叫 `render()`。 |
| `changeCompletedPage()` | 切換完成區頁面與播放轉場。 |
| `changeAppealPage()` | 切換申訴區頁面與播放轉場。 |
| `resize` 事件 | 延遲 120ms 後重新繪製，以更新自適應頁數與卡片間距。 |

## 7. 維護注意事項

- 新增任務狀態時，需同步更新 `showTaskInfo()`、`openTaskDialog()`、`moveTask()` 與 `render()` 的篩選規則。
- 狀態流轉的規則目前是：只有完成任務能提出申訴；撤銷申訴後一律回到完成區。
- 若調整卡片尺寸，請同步檢查 `getPageSize()` 與卡片間距計算中的 `cardWidth`，避免分頁上限與實際視覺寬度不一致。
- 申訴區與完成區的懸停效果不應改為強制置頂，否則可能遮蔽其他卡片，造成無法選取。
